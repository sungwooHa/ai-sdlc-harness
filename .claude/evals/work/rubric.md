# Independent work assessment

Keep this rubric and the external grader outside the worker's checkout and prompt. Give the worker
the ordinary case request, source and real authorization. Preserve the original failed or denied
run when repairing or retrying. Public fixtures contain existing product contracts, not this rubric.

## Code outcomes

| Case | Required outcome | What the external grader establishes |
|---|---|---|
| field-repair | Input contracts, independent bank/account values and evidence-based notices survive creation and editing | Leading zeros/empty/overlong segments, account characters, bank switching, full phone identity, notices and optional account |
| batch-finish | The intended accumulated set can finish; partial work and uncertain submissions remain recoverable | Untouched/partial/complete next form, empty set, stable request on unknown retry, matching completion and draft reset |
| behavior-refactor | Existing CLI behavior is preserved while duplicate structure is simplified | Fixed input/output corpus including absent/null/empty/zero/leading-zero values, error results and continued processing |

The grader runs candidate code and can fail on syntax/import/runtime problems. PASS means those
code contracts passed. Inspect the actual diff for scope and useful refactoring; a no-op can
preserve behavior without completing the requested structural improvement. A grader is not an OS
sandbox, and a passing result never proves an independent review or a browser action occurred.

## Work and stage continuity

Inspect raw tool/delegate results and artifacts against the task's actual permission boundary.
Record each item as passed, failed or unverified, with its source/build and evidence:

- The selected route matches the requested outcome; read-only work and internal refactoring do not
  acquire an unnecessary UI/interview workflow.
- Settled constraints reach the spec and plan without invented policy, repeated decisions or
  unsupported claims of approval. A preapproval stop is separate from completed implementation.
- The plan includes a usable reproduction/baseline and criterion-level proof. The final diff
  respects allowed files and actual project guards.
- Tests/commands and required delegation actually return results. The final artifact is inspected
  independently of the worker's success wording.
- Missing behavior returns to specification, infeasible proof to planning, and wrong behavior to
  implementation. Repairs retain settled decisions and rerun affected evidence.

## Browser outcomes for staff cases

Use the normal app controls, synthetic records and the intended local HTTP/SQLite backend.
Follow the repository's web-acceptance contract in mobile, tablet-web and monitor environments.
Use separate trials or explicit source receipts when combining accepted repairs from different cases.

For field repair, exercise typing, selection/paste and bank changes, including independent account
values and leading zeros. Navigate away and resume the draft, submit a valid employee, then leave
and freshly read the saved values. Check the monthly notice without an invented weekly schedule.
Record native IME/touch capability separately; emulated viewport size does not prove either.

For batch finish, accumulate two complete rows, finish on the untouched next form, and freshly read
exactly two saved employees. Also attempt completion with a partly written next row and verify it
is retained, not silently omitted. Resolve it intentionally before submission.

Run recovery against a server started with `--drop-response-once`: the first new batch commits
before its response is dropped. Observe an uncertain result; close/resume or reload, query the
same request or retry it, and verify the database still contains exactly the intended rows.
Keep a fresh SQLite read as supporting persistence evidence, alongside actual UI operations.

Missing browser/backend/input execution remains unverified even when every code check passes.
These are synthetic task results, not LUNA product acceptance or evidence of general productivity.
