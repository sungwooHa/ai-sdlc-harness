# ADR-0004: 같은 변경에서 승인한 경로는 다음 리비전에서도 고칠 수 있다

- 상태: accepted
- 날짜: 2026-10-14
- 대체함: 없음
- 대체됨: 없음

## 배경

합의 게이트는 리비전마다 `scope.json`에 적은 경로만 고치게 한다. 리뷰 지적 때문에 같은 변경의 앞 리비전이 이미 승인한 파일을 다시 고치려 해도, 지금 리비전의 scope에 그 파일이 없으면 새 리비전과 새 승인이 필요했다. 하네스 묶음 2는 승인을 6번 받았고, 그중 2번(003, 006)이 이 경우였다. 이런 재승인에는 사람이 새로 판단할 내용이 없다.

## 결정

같은 변경에서 승인됐던 리비전(승인 뒤 일시정지한 리비전 포함)의 scope 경로는 다음 리비전에 "상속 경로"로 이어진다. 그 리비전이 승인되면 상속 경로도 scope처럼 고치고, 스테이지하고, 지우거나 옮길 수 있다. 범위 밖 변경 검사, 검증의 소스 해시, 커밋 직전 스테이지 일치 검사, 필요한 HTML 판정도 상속 경로를 포함한다.

- 신뢰 근거는 작업 트리 git 디렉터리의 게이트 상태 파일뿐이다. 문서, `scope.json`, 디스크의 합의본은 상속을 만들지 못한다.
- 승인되지 않은 초안의 경로는 상속되지 않는다. 다른 변경을 준비하면 상속은 비워지고, 돌아와도 복원되지 않는다.
- 상속 경로는 prepare 출력(`inherited_paths`)과 승인 도전값에 들어간다. 사용자가 승인하는 목록과 실제 권한이 같다.
- 새 경로, 범위 확대, 계획 변경에는 지금처럼 새 승인이 필요하다. 고정된 intent·spec·plan·scope도 그대로다.

## 검토한 대안

- **리비전별 scope 유지(현행):** 단순하지만 리뷰 수정마다 판단 없는 재승인이 생긴다.
- **디스크의 `agreements/*/scope.json` 합집합:** 상태 파일 없이 계산할 수 있지만 신뢰 근거가 에이전트 작업 폴더로 나간다.
- **리뷰 수정 때 계획 고정 완화:** 계획 변경까지 승인 없이 열리므로 거절했다.

## 결과와 감수한 비용

리뷰 수정이 앞 리비전 파일에 닿아도 승인 명령을 다시 입력하지 않는다. 대신 두 가지 비용을 감수한다.

- 상속 경로는 지금 리비전의 검증 명령으로만 검증된다. 리비전마다 전체 테스트를 검증 명령으로 두면 덮인다.
- 상속은 같은 변경 안에서 되돌릴 수 없다. 범위를 좁히려면 새 변경을 시작한다.

## 재검토 조건

- 상속 경로 때문에 의도하지 않은 수정이 커밋에 들어간 사례가 생길 때
- 리비전마다 검증 명령이 달라 상속 경로가 검증되지 않은 채 남는 일이 반복될 때
- 리뷰 수정 리비전이 줄지 않을 때
