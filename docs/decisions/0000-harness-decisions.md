# ADR-0000: 하네스 결정 기록

- 상태: accepted
- 날짜: 2026-10-29
- 대체함: 템플릿의 옛 하네스 ADR 0001–0004(이 문서로 합침, 원문은 템플릿 저장소의 git 이력)
- 대체됨: 없음

> 하네스 결정의 살아 있는 기록이다. 하네스를 바꿀 때마다 이 문서를 제자리에서 고치고 날짜를 올린다.
> **변경 이력은 `git log -p -- docs/decisions/0000-harness-decisions.md`.** 결정이 옮기는 행은 [`PLAYBOOK_MAP.md`](../standards/PLAYBOOK_MAP.md).
> 2026-10-25 pilot은 당시의 실험 기록이다. 요청·작업 분기와 단계 인계 절차는 #11에서 반영됐으며,
> 실제 작업 전체의 성공·일반 효과는 별도 증거가 필요하다. 기존 승인·산출물·보호 정책은 유지한다.

## 배경

하네스 규칙은 외부 기준 없이 리뷰 지적마다 늘었다. 커밋의 약 44%가 fix였고 대부분 셸·git 옵션·트레일러 텍스트 파싱에 몰렸다.
텍스트를 파싱하는 게이트는 우회를 다 막지 못하면서 사람과 에이전트를 함께 붙잡았다(오타 하나에 사람 행동 11회, UI 기능 하나에 약 18회).
변경 산출물은 커밋되지 않아 누가 무엇을 요청·승인했는지 git에 없었다(p7과 반대).
2026-10에 잣대를 Anthropic "AI-Native SDLC Playbook"(`docs/references/anthropic-ai-native-sdlc-playbook.pdf`)으로 정하고 하네스를 다시 세웠다.

## 검토한 대안

- `defaultMode: "plan"`: intent·spec을 쓸 수 없고 서브에이전트는 막히지 않는다(spike). 거절.
- Bash 쓰기까지 게이트: 셸 파싱이라 반쪽 강제가 된다. 거절하고, 빈틈은 가이드·PR 리뷰·evals가 덮는다.
- 계획–diff 동기화 훅(p20 7단계): 반쪽 강제. 거절하고 PR 리뷰가 본다.
- 합의 게이트 유지(경로 범위·리비전·승인 도전값): 사람 행동이 오타 11회·UI 기능 약 18회였다. 거절.
- 변경 산출물을 로컬에만 두기(옛 원칙 "이력은 PR"): 감사 기록이 없다(p7). 거절.
- 하네스 결정도 결정마다 새 ADR: 현재 유효한 결정이 흩어진다. 이력은 git이 맡으므로 한 문서로 둔다.
- 응답 문구 정규식 evals 유지: 행동이 아니라 문구를 잰다. 거절.

### 요청 결과별 분기 pilot (2026-10-25 당시 실험·미채택 기록)

운영 중 반복된 개입을 개선하기 위해 요청 유형별 종료 조건을 시험한다. 사용자의
"순서대로 실행해보자" 요청에 따라 실험용 로컬 패치와 검증을 진행하며, 이는 공통 기본값 채택이나
행동 개선의 확정이 아니다. 이 절은 새 accepted 결정 번호를 부여하지 않는 실험 기록이다.
이하 결과는 당시 상태를 보존한다. 이후 절차의 적용 여부는 2026-10-29 절을 따른다.

- **대응 행**: S3.4 `Met → Met`, S3.5와 S4.2 각각 `Partial → Partial`. 기존 기준 충족 상태를
  올리거나 실제 작업 평가가 구현됐다고 선언하지 않는다.
- **변경 범위**: `AGENTS.md`의 pointer, `docs/standards/AGENT_HARNESS.md#requested-outcomes`의
  분기·종료 조건, `.agents/skills/__PREFIX__-implement/SKILL.md` description이다.
  `PLAYBOOK_MAP.md`와 이 문서는 그 실험의 근거·상태를 기록한다.
- **시험할 행동**: 조사·설계 비교·리뷰는 요청한 답변·대안·findings로 종료하고, 구현 요청은
  재현·수정·검증 또는 acceptance criteria 확인까지 진행한다. 복합 요청은 이미 요청한 결과까지
  연결하되 요청하지 않은 수정·인터뷰·승인 단계를 만들지 않는다.
- **보존하는 정책**: D2/D3/D5/D6의 산출물·계획 승인·권한·오케스트레이션 및 현 구현 스킬 본문,
  manifest·hook·보호 경로·비밀 스캔·모델/런타임 설정은 바꾸지 않는다. 쓰기 route의 선택은
  계획 승인 마커를 만들거나 기존 쓰기 workflow를 대체하지 않는다.
- **검증 상태**: 분기 지침 5파일 상태와 아래 stdin 수리 상태에서 각각 `pnpm test:harness`와
  fresh-init 회귀가 통과했다. 이 결과 문구의 후속 갱신은 checker·diff 검사로 확인한다.
  LUNA의 독립 CLI 과제와 CoLAB H14를 양호스트·양비교안으로 확인했으나 개선 우위는 관측하지 못했다.
  LUNA 산출물은 외부 검사를 통과했지만 Claude의 자체 실행과 보호 경로 무변경 검사는 충족하지
  못했다. CoLAB H14는 모두 원 채점과 무변경 검사를 통과한 smoke이며 H18은 입력 오염으로 제외한다.
  이는 전체 프로젝트·원본 템플릿의 실제 모델 실행이나 일반 성능 개선을 검증한 결과가 아니다.
- **평가 도구 결함 수리**: 호출자의 heredoc·pipe 표준입력이 모델 CLI에 상속되는 결함을 fake host로
  재현해, 모델 subprocess에만 `stdin=DEVNULL`을 적용한다. 호출자가 입력을 공급해도 fake host가
  EOF를 받는 회귀로 확인한다. 관측된 평가 오염과 같은 원인의 수리이며, pstack의 추가 메커니즘이나
  분기 pilot 효과의 근거가 아니다. 승인·가드·모델·스냅샷·지표·CLI 옵션 정책과 위 상태는 유지한다.
- **평가 수명 정리 수리 (2026-10-26)**: CLI의 정상·비0 종료 뒤에도 직접 자식이 남아 평가 반환 후
  쓰는 현상을 fake CLI로 재현했다. 모델 실행마다 전용 process group을 만들고 반환 경로와 무관하게
  정리한다. 자식이 stdout/stderr를 상속해도 EOF를 기다리지 않도록 private 임시파일로 출력을 수집한다.
  독립 프로세스 생존과 기존 exit·trace 판정·stdin EOF를 회귀로 확인하며, 새 timeout
  정책·flag·스키마·권한 예외는 추가하지 않는다. 현재 POSIX의 같은 그룹만 다루며 detach 정리는 미검증이다.
- **채택 판단**: 기준 운영판과 실험판의 동일 과제·환경·예산에서 결과와 실제 도구 기록을 비교한다.
  구조 검사만으로 승격하지 않는다. 범위 밖 편집이나 기존 승인·가드의 약화가 나타나면
  성공으로 세지 않고 원인을 분리한다. 결과가 나오면 이 절의 근거와 재검토 상태를 갱신한다.

## 결과와 감수한 비용

얻는 것: 사람의 주의가 게이트(계획 승인, PR 머지)에 모인다(p9). 요청·승인·산출이 git에 남는다.
초기 정리의 코드 줄 수 목표는 당시 범위의 기록이다. 이후 검진 확장은 재현된 실패와 회귀 증거로
정당화하며, 코드 양이나 문서 분량 자체를 품질·생산성 효과로 보고하지 않는다.

감수하는 비용과 빈틈:

- **Bash 쓰기·MCP 편집 도구**: `sed -i`·리다이렉트·`python -c`나 Serena 같은 MCP 편집 도구는 plan-first를 거치지 않는다. AGENTS.md, PR 리뷰, evals가 덮는다.
- **마커의 뜻**: "이 세션이 마지막으로 plan mode에 들어간 뒤(EnterPlanMode 호출, 또는 plan mode에서 프롬프트를 보냄) 계획을 승인받았다"이지 "이 변경의 계획이 승인됐다"가 아니다. 같은 세션에서 다른 계획으로 승인 상태가 이어질 수 있다. 오케스트레이터가 EnterPlanMode를 부르면 마커가 지워져 진행 중인 구현자가 막히므로, 백그라운드 구현자가 끝난 뒤에만 부른다. `/clear`·새 세션은 다시 승인해야 한다.
- **우회 변수와 git hook**: `HARNESS_PLAN_APPROVED=1`은 사람용이지만 에이전트가 하위 `claude -p`에 넘기면 게이트를 건너뛴다. deny 규칙과 Codex rules는 에이전트의 알려진 철자만 막고, 사람은 git hook을 언제든 건너뛸 수 있다. 비밀 스캔·pre-push는 로컬에서만 돈다.
- **CI 없음**: `docs/examples/`는 비활성이라, 가이드 규칙의 마지막 확인은 사람의 PR 리뷰다.
- **닫힌 실패**: plan-first는 payload를 읽지 못하면 거절한다. 스크립트 버그가 모든 편집을 막을 수 있어 테스트와 우회 변수로 대비한다.
- **Codex 배선**: 이 템플릿은 대응 세션 plan-first·보호 경로·포매터 hook을 설치하지 않는다.
  AGENTS.md·스킬·설정한 git hook을 따르며, 제품 전체의 hook 지원 부재를 뜻하지 않는다.
- **pre-push 전체 테스트**: 느리면 푸시가 늦어진다.

- 우회(Bash 쓰기, hook 건너뛰기)가 PR 리뷰에서 반복되면 CI 활성화를 먼저 검토한다.

- playbook 새 판이 나오거나 `PLAYBOOK_MAP.md`의 행 상태가 바뀌면 이 문서를 고친다.
