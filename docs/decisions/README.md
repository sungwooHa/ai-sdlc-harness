# 오래 유지할 결정 — ADR

ADR은 다음 사람이 “왜 이렇게 했지?”를 다시 조사하지 않도록 남기는 짧은 결정 기록입니다.
작업별 spec/plan/HTML은 로컬 합의본과 PR로 전달하고, 여러 작업에 영향을 주는 결정은 여기에 커밋합니다.

## 언제 남기나

- 시스템 경계, 주요 의존성, 데이터 소유권 등 구조를 정하거나 바꿀 때
- 여러 곳이 따르는 API·데이터 계약, 보안·배포·운영 정책을 정할 때
- 하네스의 승인·검증·완료 조건이나 사람과 에이전트의 역할을 바꿀 때
- 기존 결정을 뒤집거나, 비용 때문에 선택하지 않은 대안을 이후에도 알아야 할 때

단순 버그 수정, 문구·스타일 수정, 영향이 국소적인 구현 선택에는 쓰지 않습니다.
결정이 그대로라면 기존 ADR을 참조합니다. 파일 수나 PR 크기만으로 ADR 필요 여부를 판단하지 않습니다.

## 최소 작성 방식

`_template.md`를 복사해 `0004-<slug>.md`처럼 번호와 이름을 붙입니다. 한 결정에 한 문서,
가능하면 한 페이지로 씁니다. 번호는 재사용하지 않고 충돌은 머지 전에 정리합니다.

필수 내용은 상태·날짜, 배경, 결정, 검토한 대안, 감수한 비용, 재검토 조건, 근거입니다.
상태는 `proposed`(제안), `accepted`(합의), `superseded`(다른 ADR로 대체)를 사용합니다.
실제 합의 근거가 없으면 accepted로 쓰지 않습니다. 아직 없는 PR 주소나 승인자를 만들지 않습니다.
이 저장소의 초기 ADR은 설계 대화에서 합의한 방향을 기록하며, 수정 코드 전체의 승인·머지를 의미하지 않습니다.

## 합의·구현·PR 연결

1. 구현 전 spec/plan에 결정 초안과 대안을 넣고 관련 ADR을 참조합니다.
2. 새로 쓸 ADR과 대체 표시할 기존 ADR의 경로를 scope.json에 넣어 함께 합의합니다.
3. 승인 후 합의한 내용을 ADR로 저장합니다. 결정이 바뀌면 먼저 재합의합니다.
4. PR에서 ADR을 링크하고 실제 가치·검증 결과는 PR에 남깁니다. ADR에 실행 로그를 복사하지 않습니다.

이전 결정을 바꿀 때는 새 ADR을 만들고, 이전 문서에는 superseded 상태와 새 문서 링크만 추가합니다.
새 문서의 대체함은 이전 ADR, 이전 문서의 대체됨은 새 ADR로 서로 연결합니다.
형식은 `- 대체함: [ADR-0001](0001-example.md)`이며 해당 없는 쪽은 `없음`입니다.
제안 단계에서는 두 필드를 없음으로 두고 배경에서 대체하려는 결정을 설명합니다.
원래 이유를 새 결정에 맞춰 고쳐 쓰지 않습니다. 오탈자·깨진 링크 수정은 가능합니다.

ADR의 상태는 승인 권한이 아닙니다. 현재 훅은 ADR 파일에도 승인 범위 검사를 적용하지만,
새 ADR이 있는 변경에서는 필수 항목·날짜·번호·상태·양방향 대체 링크를 추가 검사합니다.
“이 작업에 ADR이 필요한가”, “대안과 근거가 충분한가”를 자동 판정하지는 않습니다.

## 하네스에서 사용

Claude에서는 `/__PREFIX__-adr`, Codex에서는 `$__PREFIX__-adr`로 요청하거나
“ADR 만들어”, “이 결정을 기록해”라고 요청합니다. 스킬은 자동 발견도 가능합니다.
예: “파일 저장소를 교체하기로 한 이유와 대안을 ADR로 남겨줘.”
기존 승인 범위에 포함되어 있으면 다시 승인받지 않고, 없으면 초안과 경로를 합의에 포함합니다.

Stop 훅은 작성된 ADR의 오류가 남으면 완료를 막고, pre-commit은 실제 스테이징된 문서를 검사합니다.
검사는 `python3 scripts/adr-gate.py --all`로 미리 실행할 수 있습니다.
제안 중이거나 명시적으로 일시정지한 상태는 완료와 구분합니다.

## 먼저 제안받기

합의 준비 직전의 훅이 예정된 파일 범위에서 인증·권한, 데이터·공유 계약, 주요 의존성,
배포·운영, 하네스 정책의 변경 후보를 찾습니다. 에이전트는 실제 결정과 기존 ADR을 확인한 뒤
필요하면 제목·남길 이유·결정 초안을 짧게 제안합니다. 단순 수정이면 제안하지 않습니다.
같은 변경의 같은 후보 경로는 반복 알리지 않으며, 제안 자체가 승인이나 작성 의무는 아닙니다.
파일 경로 기반 탐지라 모든 결정을 찾지는 못합니다. 규칙은 harness.yaml의 adr_suggestions에서
조정하거나 enabled를 false로 꺼둘 수 있습니다.
