# ADR-0002: HTML은 구현 전 합의, PR은 가치 리뷰에 사용한다

- 상태: accepted
- 날짜: 2026-09-14
- 대체함: 없음
- 대체됨: 없음

## 배경

사람이 코드와 긴 문서만으로 무엇을 만들고 어떻게 동작할지 이해하기 어렵다.
구현이 끝난 뒤 처음 결과를 보여주면 잘못 이해한 요구를 고치는 비용도 커진다.

## 결정

설명서·목업·흐름·아키텍처의 네 관점은 기존 적용 조건에 따라 구현 전에 초안으로 제시한다.
설명서를 입구로 연결해 사람이 구현 방향을 합의할 수 있게 한다. 합의본은 보존하고
구현 후 실제 결과는 별도로 갱신한다. PR에서는 합의한 기대·실제 변화·증거와 미검증 가치를 비교한다.

## 검토한 대안

- HTML을 기본 흐름에서 제거: 작성량은 줄지만 사람이 결과를 상상해야 하는 부담이 남는다.
- 구현 후 완료 보고로만 생성: 구현 전에 오해를 발견할 기회를 잃는다.
- 합의본을 실제 결과로 덮어쓰기: 비교 기준이 사라지고 기대를 사후에 바꿀 수 있다.

## 결과와 감수한 비용

구현 전에 오해를 발견하고 결과를 같은 기준으로 비교할 수 있다. 초안 작성과 두 버전 관리 비용이 든다.
목업은 실행 증거가 아니며, 테스트 통과만으로 사용자의 가치가 확인되지는 않는다.
HTML이 실제로 인지부하를 줄이는 효과는 사용하면서 확인해야 한다.

## 재검토 조건

사람이 여러 관점을 반복해서 읽지 않거나, 승인 뒤 요구 오해가 계속되거나,
초안 작성 비용이 얻는 이해보다 커지면 표현·적용 조건을 조정한다.

## 근거

- 2026-09-14 설계 대화: 사용자가 HTML의 목적을 인지부하 해소와 구현 전 합의로 명확히 하고,
  PR을 가치 리뷰로 사용한다고 설명했다.
