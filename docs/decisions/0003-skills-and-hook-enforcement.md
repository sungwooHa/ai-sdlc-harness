# ADR-0003: 스킬이 안내하고 훅이 실행 조건을 검사한다

- 상태: accepted
- 날짜: 2026-09-14
- 대체함: 없음
- 대체됨: 없음

## 배경

에이전트 지침에 승인·검증 절차를 적는 것만으로는 생략이나 잘못된 완료 보고를 막을 수 없다.
사람에게 판단을 맡기는 단계와 시스템이 확인할 조건을 분리해야 한다.

## 결정

스킬은 초안·범위·검증 계획의 준비와 진행 안내를 맡는다. 훅은 사용자 승인 이벤트와
변경 범위·검증 기록·완료 조건을 검사한다. 문서의 approved 표시나 승인 이름의 스킬 호출을
승인 권한으로 사용하지 않는다. 사람의 가치 판단을 훅이 대신했다고 주장하지 않는다.

## 검토한 대안

- 지침서와 스킬만 사용: 유연하지만 실행 시점의 누락을 제어할 수 없다.
- 커밋·CI 검사만 사용: 구현 전 합의 누락을 발견하기에는 늦다.
- 모든 의미 판단을 자동화: 파일·검증 기록 검사로 사람의 이해와 가치 판단까지 증명할 수 없다.

## 결과와 감수한 비용

현재 구현은 입력·도구 실행 전·종료 훅과 pre-commit을 연결한다. 정확한 파일 범위와
코드 해시에 연결된 검증 결과를 사용하므로 범위 변경·코드 수정 시 재합의나 재검증 비용이 든다.
호스트별 도구 형식과 신뢰 설정을 관리해야 하고 미지원 도구에는 별도 연결이 필요하다.
이 구현 세부사항은 제품 사용성을 보며 조정할 수 있다.

훅은 OS 보안 격리가 아니다. 훅을 거치지 않는 경로, 직접 터미널 조작, 신뢰한 검증 명령의
호스트 권한은 별도 경계다. 실제 앱에서의 훅 활성화와 실행 확인이 필요하다.

## 재검토 조건

지원 도구에서 우회가 발견되거나, 정상 작업이 반복해서 막히거나, 호스트의 훅 형식이 바뀌면
연결과 검사 방식을 다시 검토한다. 더 강한 격리가 필요하면 별도 실행 환경을 검토한다.
