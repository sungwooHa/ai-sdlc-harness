## 문제

프로젝트에서 개선한 규칙과 공통 템플릿의 앞단 흐름이 달라지고, 질문·문서·구현 검증이 서로 연결되지 않는다. 작은 구현 과제의 성공만으로 네 단계 전체가 작동했다고 판단할 수 없다.

## 바라는 결과

그릴링의 결정이 스펙의 관찰 가능한 동작, 계획의 실행·검증 방법, 구현의 실제 증거로 이어진다. Claude/Codex는 사용 가능한 도구로 같은 책임과 완료 기준을 따른다. README에서 실제 기능과 미검증을 구분할 수 있다.

## 가치 가설

이미 합의한 내용을 되묻는 수고와 사용자 피드백으로만 발견되는 종료·복구 누락을 줄일 수 있다. 감소율과 일반 생산성은 이번 변경만으로 입증하지 않는다.

## 제약

기존 plan-first·보호 경로·비밀 검사·git hook·필요 산출물 정책은 유지한다. 외부 공개 인터페이스·의존성을 추가하지 않는다. 프로젝트별 도메인 규칙은 공통 템플릿에 넣지 않는다. 새 승인 마커나 trust를 만들어 native 성공으로 가장하지 않는다.

## 열린 질문

공통 템플릿의 단계별 승인 자체를 없애는 정책 변경은 이번 범위에 없다. 기존 승인과 결정은 재사용하고 새 실질 결정만 확인한다.

## 비범위

LUNA 제품 코드·운영 데이터·배포·기존 PR 머지. LUNA 전용 readonly/work runner를 공통 템플릿으로 복사하는 작업. 전 프로젝트 자동 동기화 도구와 CI 자동 활성화.
