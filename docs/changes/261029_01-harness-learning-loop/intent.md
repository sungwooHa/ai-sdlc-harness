# 의도: 실무에서 배운 개선을 다시 검증할 수 있는 공통 하네스

사용자는 Anthropic Playbook의 책임·가드·환류, pstack/poteto의 작업 분기·실제 작업 평가,
LUNA의 반복 UX 실패·스킬 충돌 경험을 기준으로 공통 템플릿을 개선하길 요청했다.
2026-10-29 현황 대조 뒤 제시한 다섯 단계에 “ㅇㅇ 순서대로 작업해라”로 실행을 승인했다.

- D1: 현재 상태·정책 정합성 → LUNA 공통 검진 → 실제 과제 평가 → 연결 실행 → CI·새 초기화본 순서.
- D2: 프로젝트 도메인 정책과 승인·보호 규칙은 유지한다. LUNA의 문서 선택 정책을 공통 기본값으로 복사하지 않는다.
- D3: Claude/Codex의 같은 작업 책임을 검증하되 도구·가드 차이를 숨기지 않는다.
- D4: 실제 입력·완료·중단·복구·저장 결과를 검증하며 호출 기록이나 구조 검사로 결과를 대체하지 않는다.
- D5: 실패·거절·미검증과 원본을 보존하고, 일반 효과는 비교 증거가 있을 때만 주장한다.

범위는 공통 템플릿이다. LUNA 운영 제품·사용자 데이터·기존 미커밋 변경·프로덕션 배포는 대상이 아니다.
새 모델 공급자·의존성·전역 설정·브랜치 보호 설정을 추가하지 않는다.
